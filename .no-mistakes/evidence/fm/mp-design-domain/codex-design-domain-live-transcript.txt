  ### Name the facts

  “Event” is too broad here. AGENTS.md:184 calls each status line a historical wake event, never current-state truth. The code also has durable wake queue rows,

  Current ownership is split: the classifier finds actionable lines; the wake library annotates rows; the drain builds sections and commits presentation cursors.
  Classifier (bin/fm-classify-lib.sh:2281), annotation (bin/fm-wake-lib.sh:2653), drain (bin/fm-wake-drain.sh:780).

  ### Two interfaces

  A. Pure planner

  plan(snapshot, claimedRows, presentationReceipts)
    -> {text, proposedReceipts, warnings}

  Caller captures files, writes text, then commits receipts. Easy to test with fixed inputs. But its interface exposes snapshot and receipt rules; callers still
  coordinate races and failed output. Deleting this module would leave much complexity in the drain. Its depth is limited.

  B. Presentation owner

  presentWorkerWakes(home, claimedRows, output)
    -> {presentedRowIds, statusReceipt, warnings}

  The module captures one status endpoint, reads unread lines, applies decision and backstop rules, writes the presentation, and commits status receipts only after
  successful output. The caller retains actor claims and generation-bound queue acknowledgement. Local files are substitutable in tests; output has concrete stdout and
  test-buffer adapters. This seam gives better depth and locality without inventing a network port.

  ### Race tests that decide the design

  • Duplicate wakes: collapse repeated rows for display, retain their sequence identities for actor-scoped acknowledgement. Do not equate a duplicate row with a duplicate
    status declaration.

  • Delayed row: an empty-queue backstop may show done: first; a later direct signal must still annotate its unread line. Existing tests require these independent
    receipts. Test (tests/fm-wake-drain-outcome-backstop.test.sh:189).

  • done: then late working:: show both as historical declarations and reconcile current state separately. The span classifier retains terminal lines, but the empty-queue
    backstop currently examines the latest line; it could miss done: in this sequence. The activity fold can also reopen working by append order. Backstop (bin/fm-wake-
    drain.sh:355), activity fold (bin/fm-classify-lib.sh:2063). An [at=] timestamp cannot settle that race: its documented purpose is history, not state ordering. Time
    contract (bin/fm-classify-lib.sh:430).

  instead of checking only the latest line; keep fm-crew-state.sh authoritative for current-state reconciliation. A later writer change could add a per-task logical
  revision to distinguish late delivery from resumed work. Without that revision, label the pair ambiguous.
