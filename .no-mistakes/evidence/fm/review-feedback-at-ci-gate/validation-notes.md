# Test phase evidence

The real `bin/fm-brief.sh`, `bin/fm-promote.sh`, and public `fm_dod_block` interface were executed in disposable homes inside the assigned worktree. Markdown files here are their emitted worker instructions. Promotion metadata records the persisted scout-to-ship transition. All disposable homes were removed.

The oracle is the supplied user intent and accepted branch decisions. Validation checks the generated instruction contract, including adversarial no-parked-gate, early-green, already-synchronized, and non-GitHub cases. It does not claim that a language model followed the instructions or that remote pull-request operations ran. No running pipeline was controlled.

Focused existing tests executed: `test_ship_modes_generate_clean_briefs`, `test_forge_selection_renders_correct_cli`, `test_no_mistakes_dod_wording`, `test_no_mistakes_dod_green_detection`, `test_no_mistakes_dod_ci_gate_feedback`, `test_no_mistakes_dod_ci_wait_uses_configured_pause_verb`, and `test_pr_based_dod_requires_non_draft` from `tests/fm-brief.test.sh`; and `test_arm_plumbs_a_configured_budget_into_the_check_shim` from `tests/fm-contributions.test.sh`. The latter uses a disposable forge boundary and is supplementary regression evidence, not a live forge check. All passed. The drivers load existing definitions and invoke only these selectors; no full suite, lint, formatting, or static analysis ran.

The first promotion driver incorrectly required the entire immediate-delivery message to appear verbatim in the relaunch brief. These have different envelopes. That driver assertion was corrected to require the independently specified feedback and pause contract in both outputs, and both promotion scenarios were re-driven successfully. This was a test-driver error, not a product failure.

No rendered GUI changed; the product surface is generated Markdown instructions. Original output is retained instead of screenshots. No source or test files were changed.
